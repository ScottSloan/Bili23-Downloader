## 功能与架构

项目提供投稿、番剧、课程、收藏夹、个人空间等内容的解析；支持画质与编码选择、并发下载、断点续传、失败重试、字幕弹幕、封面章节、NFO 元数据和命名分类。GUI 使用 PySide6 与 Fluent Widgets，网络使用 httpx，任务存储使用 SQLite，媒体处理使用 FFmpeg，并提供默认关闭的 MCP 接口。

| 路径 | 主要职责 |
| --- | --- |
| `src/gui` | 主窗口、列表模型、设置、下载选项 |
| `src/util/parse` | 链接解析、条目获取、媒体预览、附加内容 |
| `src/util/download` | 任务调度、分块下载、持久化、合并 |
| `src/util/network` | 请求、代理、CDN、错误分类 |
| `src/util/auth` | 扫码、短信和 Cookie 登录 |
| `src/util/ffmpeg` | 命令构造、子进程执行、进度与终止 |
| `src/util/mcp` | 本地自动化接口、协议与桥接 |
| `test` | 下载、配置、解析、命名、GUI 等测试 |

下载流程为：解析链接 → 获取条目 → 携带账号 Cookie 获取播放信息 → 选择视频流与音频流 → HTTP Range 分块下载 → FFmpeg 封装 → 保存附加内容并更新任务状态。直接下载媒体数据，无需录屏；会员内容依赖账号已有访问权限。

### 已有工程能力

下载器已有线程安全令牌桶、重试错误分类、分块偏移记录和响应完整性检查。SQLite 使用线程本地连接、WAL 与忙等待超时。FFmpeg 执行器已有进度处理、输出保留上限、无输出看门狗和停止控制。项目已有 pytest 与 Ruff 配置，CI 包含 Python 3.11、3.13 测试矩阵。

后续应复用并验证这些能力，避免重复实现。已有测试配置不等于当前测试全通过，开发前需实际执行相关检查。

## 实际下载验证

测试链接：`https://www.bilibili.com/bangumi/play/ss33585`。

| 项目 | 结果 |
| --- | --- |
| 账号 | 用户在本机扫码登录的会员账号 |
| 解析 | 返回 420 个条目，本次仅选第一集 |
| 下载内容 | 《中国通史》第 1 集《中华道路》 |
| 请求规格 | 1080P+、AVC、MP4 |
| 任务显示 | 1080P 高码率、192K 音质 |
| 下载数据量 | 1,877,406,030 字节，约 1.88 GB；与最终封装体积可能不同 |
| 耗时 | 约三分钟，观察到速度约 9 至 12 MB/s |
| 实际文件 | 1920×1080、25 fps、H.264 High、AAC 双声道、48 kHz |
| 实际时长 | 45 分钟左右 |
| 检查 | FFmpeg 整片音视频解码退出码为 0，无错误输出 |

任务显示的音质档位为 192K，而最终 AAC 音轨检测约为 320 kb/s。该差异尚未定位，可能涉及档位名称、接口信息或媒体选择逻辑，不能直接判定为下载错误。应分别展示请求选项、平台档位和实际文件信息。

测试通过临时启用的本机 MCP 接口创建单集任务；结束后接口已关闭、临时令牌已清除。文档和测试记录不保存 Cookie、令牌或个人账号信息。

单次成功下载证明该内容与当前网络环境可用，尚不能证明断网恢复、强制退出恢复、地址过期、多任务及其他平台均可靠。

## 阶段一 实际媒体规格校验

### 实现范围

新增独立媒体探测模块，用 ffprobe JSON 输出获取容器、时长、音视频轨道、编码、分辨率、采样率及可用码率信息。先核对 Windows、macOS、Linux 发行包是否包含 ffprobe；当前本机只配置了 FFmpeg，不能假设 ffprobe 已存在。支持定位同目录工具和系统工具，探测缺失应明确展示“未验证”。

区分三类信息：用户请求规格、平台实际选择结果、最终文件规格。码率未知时保留未知，不能按文件总码率伪造音频码率，也不能把 192K 等档位直接当作最终实测值。

合并成功后在后台进行快速校验，检查文件可读、必要轨道存在、时长合理，以及可比较的分辨率和编码信息。合法的音频单独下载不能被要求包含视频轨。精确画质映射、时长容差和警告等级应通过样例确定。

### 状态与兼容

探测运行需有超时、取消和有限输出。普通规格差异显示警告；缺失必要轨道、无法解析等明确错误提供诊断与重试入口。探测工具缺失不得把已成功下载的文件误判为损坏。验证结果与原下载状态分开保存，旧任务无结果时显示“未验证”。数据库新增字段或表需要迁移和旧数据兼容测试。

整片解码作为用户主动选择的深度检查，不默认对所有下载执行。

### 验收标准

- 正常音视频、音频单独下载、缺失轨道、损坏文件、未知码率和探测超时均有明确结果。
- 探测不阻塞 GUI，也不额外占用合并额度造成队列阻塞。
- 重启后验证信息仍可读取，旧数据库可以正常打开。
- 对本次样例能分别解释音质档位与实测码率，不以两者数字不同直接报损坏。

相关入口：`src/util/ffmpeg`、`src/util/download/downloader/merger.py`、`src/util/download/task` 和下载列表模型。

## 阶段二 异常恢复测试与修复

以本地可控 HTTP 服务器提供固定媒体或二进制样本，记录 Range 请求并模拟异常。测试不依赖真实会员账号；最终文件与固定样本比较哈希。涉及进程退出时使用独立测试子进程，避免影响用户运行中的应用。

| 场景 | 验收标准 |
| --- | --- |
| 暂停与继续 | 从可信偏移续传，最终数据一致 |
| 进程强制退出后恢复 | 允许重下未持久化尾部，不跳过尚未落盘数据 |
| 连接中断、超时、5xx | 按策略重试，取消及时，次数有界 |
| 地址过期或资源变化 | 检查现有刷新逻辑；刷新后验证资源一致性，再决定续传或重下 |
| Range 被忽略、范围错误 | 不将完整响应写入错误分块位置 |
| 磁盘不足、写入失败 | 任务失败原因明确，不继续无效网络重试 |
| 合并失败或被终止 | 保留恢复所需素材，任务退出合并状态，后续任务能继续 |
| 完成记录持久化失败 | 不把尚未可靠记录的完成状态当作已完成历史 |

先运行已有相关测试，新增覆盖缺失的故障路径；仅针对复现的问题修改生产代码。记录可重复命令、失败原因和修复后的证据。

## 阶段三 大合集与集数范围选择

添加 `1-10`、`1,3,5-8` 等范围输入，明确范围对应当前列表中的展示集数。分组重复编号时要求先限定分组，避免跨组误选。处理越界、倒序、无效字符及重复范围，并给出可理解的错误信息。

下载前显示选中数量和已知总时长，体积未知时标注未知或估算，不为获取体积对全部 420 条逐一请求。分类使用接口提供的信息；无可靠分类时保留未分类，不仅凭标题判定正片或花絮。

验收包括筛选、分页、重新解析后的选择一致性，取消操作不创建任务，以及大列表操作不阻塞界面。先确认已有批量选择对话框的能力，再扩展，避免新增重复入口。

相关入口：`src/gui/dialog/misc/batch_select.py`、`src/gui/component/parse_list`、`src/util/parse/episode/tree.py`。

## 后续阶段

### 链接筛选和排序

上游 `TODO.md` 已列出空间 `tid/order`、收藏夹筛选、历史记录时间与时长、稍后再看排序等参数。先核实接口可选值，沿用 `src/util/parse/search_url.py` 保存和恢复状态。验收重点是链接往返、翻页和解析历史能够保持筛选条件。

### 性能测量和并发调整

记录下载吞吐、并发连接、重试次数、CPU、内存、磁盘写入及 GUI 响应，区分网络传输和合并时间。分别测量单任务、多任务、限速及弱网场景，再决定是否引入有上下限的自适应并发。吞吐提升必须结合错误率和资源使用评价，不以线程数量作为效果指标，不承诺固定提速比例。

### 逐步解耦核心

当前下载器直接使用 Qt 工作线程、全局配置、任务管理器和信号总线。先将纯数据结构、媒体探测、错误分类及网络策略提取为可独立测试模块，再按实际 CLI 或服务需求引入配置、存储和事件接口。保持 GUI 与 MCP 调用同一业务流程，避免一次性重写整个下载器。

## 开发与验证流程

1. 核对 fork、上游、分支和工作区；检查是否新增 `AGENTS.md`。创建独立功能分支，保留已有本地文件与用户修改。
2. 使用现有 `.venv`，安装项目声明的开发依赖；执行现有相关测试和 Ruff，记录基线失败，不将历史问题混入功能修改。
3. 按阶段一、二、三依次交付，每阶段独立提交；先覆盖关键行为，再完成最小实现与 GUI 接入。
4. 运行修改涉及的测试与检查；涉及任务状态、数据库、线程或公共接口时执行完整 pytest 回归。测试中不得写入用户真实配置和任务数据库。
5. GUI 改动手动检查浅色与深色主题、大列表操作、错误提示及取消流程；记录实际验证的平台，其他平台交由 CI 验证。
6. 真实下载仅选择明确的一集；记录规格、耗时、结果，分享日志前去除登录凭据和个人信息。临时控制服务用后关闭。
7. 更新本文实施记录。发布包涉及新工具时检查各平台打包、工具发现和工具缺失路径。
